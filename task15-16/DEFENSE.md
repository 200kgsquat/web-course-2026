# Выступление: 5–7 минут
1. **0:00–0:40, цель.** «Я сделал приложение для учёта доходов и расходов. Пользователь добавляет операции и категории, видит баланс, редактирует и удаляет записи».
2. **0:40–2:10, демонстрация.** Откройте localhost:3000. Добавьте доход 1000 и расход 150 за сегодня: баланс 850. Примените тип «Расход», откройте детали, измените сумму на 200. Вернитесь и сбросьте фильтр: баланс 800. Удалите расход. Обновите страницу: доход остался в SQLite.
3. **2:10–3:20, структура.** Покажите app/page.js, app/add/page.js, app/transaction/[id]/page.js. В client/views лежат JSX-представления; client/controllers содержит состояние и команды; client/models — доступ к данным. Серверный controllers/finance-controller.js обрабатывает HTTP; app/api привязывает маршруты; models/db.js открывает базу, models/money-model.js содержит SQL и валидацию.
4. **3:20–4:20, поток данных.** Форма передаёт JSON через fetch. Сервер проверяет сумму, дату и категорию, делает INSERT с параметрами, возвращает новую операцию. При фильтре запрос содержит type/category_id/from/to; SQL WHERE ограничивает результат.
5. **4:20–5:20, React и ошибки.** useState хранит данные интерфейса. useEffect загружает список при смене фильтра; cleanup не даёт старому ответу изменить новый экран. 400/404/500 показаны пользователю. Список отображается из массива, key использует id.
6. **5:20–6:20, проверка и ограничения.** Покажите RESULTS.txt из лабораторной 14 и запустите npm test. Локальная БД сохраняется на диске. Деплой не выполнен; в serverless Vercel SQLite на /tmp временная и не является надёжным общим хранилищем.

## Вопросы преподавателя
- **Почему useEffect, а не fetch прямо в рендере?** Рендер может повторяться много раз. Эффект запускает запрос по зависимостям и позволяет отменить обработку устаревшего ответа.
- **Зачем отдельный api.js?** Все правила запросов и HTTP-ошибок описаны один раз, UI работает с данными, а не транспортом.
- **Зачем валидация на сервере?** Клиентскую форму можно обойти прямым HTTP-запросом.
- **Почему фильтры в SQL?** Сервер отдаёт только подходящие операции; полная база не нужна клиенту.
- **Чем CSR отличается от SSR/SSG?** CSR загружает данные браузером после открытия страницы; SSR строит HTML при запросе; SSG готовит HTML при сборке. Наши операции загружаются клиентом, оболочка может быть подготовлена сервером.
- **Где сохраняется список Todo?** В №3 только массив в памяти. В React — массив состояния и localStorage. В Zen-Money — SQLite на сервере.
- **Как не наложить таймеры Simon?** Каждый id setTimeout хранится в Set и удаляется после вызова; при перезапуске оставшиеся отменяются.
- **Чем Angular отличается здесь?** TodoService внедряется через DI; ngModel связывает ввод и свойство; ngFor/ngIf управляют шаблоном.

- **Где здесь MVC?** Откройте Models/Views/Controllers в №6: SnakeModel обновляет игровое состояние без DOM, SnakeView рисует Canvas, SnakeController обрабатывает ввод и управляет циклом. Тесты модели — в task14/tests/mvc.test.js.
